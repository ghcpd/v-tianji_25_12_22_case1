## High-impact issues & surprises (must-fix / high risk) ⚠️
1. Persistence not wired
   - storage.ts exports `loadTodos` / `saveTodos` but App.tsx never calls them — todos are lost on reload.
   - File: App.tsx (initial state is `[]`; imports unused `loadTodos`/`saveTodos`).

2. Unsafe/loose runtime typing for persisted data
   - storage.ts returns `any[]`/`unknown[]` with no schema validation → corrupted localStorage can break UI.
   - Helpers in helpers.ts assume fields exist (no runtime guards).

3. Unused utilities / dead code
   - `formatDate`, `sortTodosByPriority`, `getCompletedCount` are not used in UI — potential drift between design and implementation.

4. Accessibility gaps (a11y)
   - Inputs/buttons lack accessible labels/attributes (`aria-label`, `<label>`, `aria-pressed`, keyboard focus cues).
   - `FilterBar` uses plain buttons without ARIA state semantics for toggle groups.

5. Missing UX features & edge-case handling
   - No edit/undo, no bulk actions, no priority filtering/sorting in UI.
   - ID generation uses `Date.now().toString()` — possible collisions and makes deterministic testing harder.
   - No feedback on failed localStorage operations (only console.error).

6. Testing & CI
   - No unit/integration tests or test config present.
   - No lint/build CI indicated in repo (package.json has scripts but no CI config).
