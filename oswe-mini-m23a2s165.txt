## Issues, risks & code smells (priority order)
1. Persistent storage is broken / not wired
   - `loadTodos` / `saveTodos` are imported in App.tsx but **never used** — no localStorage persistence. (storage.ts has implementation but is unused.)
   - Risk: users lose data on refresh; dead imports confuse maintainers.

2. Unused utility functions
   - helpers.ts exports (`formatDate`, `sortTodosByPriority`, `getCompletedCount`) but none are referenced anywhere. This suggests incomplete features or stale code.

3. Type safety and API surface
   - `saveTodos` / `loadTodos` use loose types (`unknown[]` / any-like return). Prefer strongly typed signatures (use `Todo[]`).
   - `sortTodosByPriority` sorts in-place (mutates input) — unexpected side effects.

4. UX / feature gaps (likely expected)
   - No edit/update for existing todos.
   - No "clear completed" or total/remaining counts in UI.
   - No sort-by-priority or createdAt ordering in UI (utilities hint these were intended).

5. Accessibility & semantics
   - Form input lacks label/aria-label. Buttons could use aria-attributes for screen readers.
   - Keyboard interactions (Enter to submit works, but more ARIA could help).

6. Testing & tooling
   - No tests present (unit / component).
   - package.json has an ESLint script but I don't see an ESLint config file — check for `.eslintrc` (may be missing).

7. Minor correctness
   - IDs use `Date.now().toString()` — OK for small apps but may risk collisions in edge cases.
   - `sortTodosByPriority` uses loose typing for `priority` string.
